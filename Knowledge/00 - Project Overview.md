# BantayAralan — Project Overview

**BantayAralan: Real-Time Student Behavior and Classroom Orderliness System** — a BSCpE thesis/capstone project at Holy Angel University by Chloe Lane B. Jose, Raynier Ronn G. Santos, and Justin Rieko S. Tolentino (proposal dated March 29, 2026).

> **The research proposal is a working draft.** Requirements, system design, UI, implementation choices, and technical decisions described anywhere in this vault may change after consultation with the thesis adviser. Nothing here should be read as finalized unless explicitly marked otherwise.

## What the project is trying to do
A computer-vision system intended to help teachers by:
- Detecting **disruptive student behavior** (e.g. standing) in real time.
- Detecting **classroom disorder** — scattered objects/trash and misaligned seats/desks.
- Logging each detection as an **event** with optional visual evidence (screenshot/video).
- Alerting the teacher — without identifying individual students.

See [[Research Proposal]] for the full background, research questions, and significance.

## Main objective
Design and develop a computer-vision-based behavior detection system that identifies disruptive student actions and classroom disorder, captures event-based visual evidence, and alerts teachers in real time — without facial recognition or long-term profiling. Full objectives: [[Research Questions & Objectives]].

## Major system components
- **Hardware** (proposed): ceiling-mounted camera, top-down camera, processing PC — [[08 - Hardware]].
- **Computer vision pipeline** (proposed): YOLO11m + ByteTrack + behavior/alignment logic — [[04 - Computer Vision]].
- **Event & evidence system** (proposed + partially prototyped in UI): [[Event Model]], [[Evidence System]].
- **Database**: SQLite — [[06 - Database]].
- **Admin UI**: one web application (`admin-ui/`) — [[UI UX Overview]].

## Research status
Design and Development Research (DDR) + quantitative experimental evaluation, not yet executed — see [[Methodology]] and [[09 - Testing & Evaluation]]. No teacher surveys, pilot deployment, or accuracy measurements have been recorded in this repository yet.

## Important constraints
- No facial recognition or student-identity recognition, no long-term psychological profiling — [[10 - Privacy & Ethics]].
- The system supports, not replaces, teacher decision-making.
- Admin UI: no live camera feed on the dashboard, no login/auth flow, one classroom only — [[UI UX Overview]].

## Important unresolved decisions
See [[12 - Open Questions]] for the full list — notably: evidence retention policy, final GUI framework for the integrated CV+GUI system, final event categories/thresholds, and whether authentication will ever be needed.
