# BantayAralan -- Admin UI (native desktop app)

A real native desktop application for the BantayAralan admin interface --
Dashboard, Events & Logs, Event Detail with video/screenshot evidence --
built with [PySide6](https://doc.qt.io/qtforpython-6/) (Qt for Python).

**No browser, no webview, no HTTP server.** Unlike the earlier prototype in
[`../admin-ui`](../admin-ui) (a Flask + HTML/CSS/JS app viewed in a browser
or a browser-based webview), this one is a genuine native GUI application:
it opens as an OS window and reads/writes a local SQLite file directly in
the same process. `../admin-ui` is left in place as a reference/alternative
-- this is the one to use if you specifically want "an application, not
something that views the web."

This is still a **UI/UX prototype with mock data**, not the real
BantayAralan system -- there is no camera, no YOLO/ByteTrack pipeline, and
no real video capture behind it. See "What's real vs. mocked" below and the
project root [`CLAUDE.md`](../CLAUDE.md).

## Running it

```bash
pip install -r requirements.txt
python run.py
```

A window titled "BantayAralan -- Admin" opens directly -- nothing to point
a browser at. Mock data seeds automatically into `data/bantayaralan.db` on
first run; delete that file to reset/reseed.

## Packaging as a standalone .exe

Not built in this session -- documented here for when you want it:

```bash
pip install pyinstaller
pyinstaller --name BantayAralan --onefile --windowed run.py
```
`--windowed` suppresses the console window (this is a GUI app). Test the
resulting `dist/BantayAralan.exe` on a clean machine before distributing --
PySide6 apps are sizable (the Qt runtime is bundled in), so expect the exe
to be roughly 80-150MB.

## What's real vs. mocked

| Piece | Status |
|---|---|
| Dashboard, Events/Logs, Event Detail screens, filters, search, sort, pagination | Real, working native UI |
| Loading / empty / no-results / error / evidence-unavailable states | Real, working code |
| Event data (42 seeded mock events, all 4 categories) | Synthetic, generated by `app/data.py` -- not from a real detector |
| Snapshot evidence | Drawn on the fly with `QPainter` (`app/snapshot.py`), not a real camera frame |
| Video evidence | **Fully simulated** -- the player (play/pause, scrub, time, volume, and a genuinely working fullscreen toggle on the app window) is real and interactive, but there is no actual video file or codec involved. See "Video evidence -- backend requirements" below. |
| System status panel | Hardcoded-true mock values |
| Authentication | None -- intentionally out of scope (admin-only, single deployment) |

## Video evidence -- backend requirements (not yet implemented anywhere)

Same gap as the web prototype -- this codebase does not implement real
event-video capture. For the Event Detail video player to show real footage:

1. A rolling frame buffer per camera, so a captured clip can include the
   period *before* the trigger, not just after.
2. On a detected event, cut a clip spanning a defined window (e.g. -10s/+10s).
3. Encode and store it (retention/storage policy is an open decision --
   see the root CLAUDE.md).
4. Associate the clip with the event row (add a `video_path` column next to
   `snapshot_available` in `app/data.py`'s schema).
5. Swap `app/video_player.py`'s simulated `QTimer` progress for Qt
   Multimedia (`QMediaPlayer` + `QVideoWidget`) pointed at the real file --
   the widget's public surface (`play()`, `pause()`, `toggle()`) is already
   shaped so this swap wouldn't touch the surrounding views.
