# Event Model

An **event** is a single logged occurrence of disruptive behavior or classroom disorder. (Use "event," not "offense" — the codebase and design brief consistently use "event.")

## Current implementation (Implemented, mock data)
Both `admin-ui/backend/db.py` and `desktop-app/app/data.py` define the same `events` table:

```sql
CREATE TABLE events (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    category TEXT NOT NULL CHECK (category IN ('standing', 'trash', 'misaligned', 'other')),
    title TEXT NOT NULL,
    description TEXT NOT NULL,
    occurred_at TEXT NOT NULL,          -- ISO 8601 timestamp
    video_available INTEGER NOT NULL DEFAULT 0,
    snapshot_available INTEGER NOT NULL DEFAULT 0,
    evidence_note TEXT                  -- shown when evidence is unavailable
);
```

- **Four categories**: `standing`, `trash` ("Trash / Scattered Objects"), `misaligned` ("Misaligned Seat"/Table), and a catch-all `other`. Note: the proposal's narrative only explicitly names three (standing behavior, trash detection, misaligned furniture) — `other` is an implementation addition, not stated in the proposal. **Changed from proposal** (additively — not a conflict, just an extra catch-all).
- All current rows are synthetic, generated by a fixed-seed random generator (`seed()` in each subsystem) — ~42 events spread across the last 7 days, not from any detector.
- No student names, IDs, or identifying content in any field.

## Working direction (per current project guidance)
- **Events do not require an event status** (no New/Reviewed/Resolved field) — see [[No Event-Status Field]].
- Both video and screenshot evidence may be associated with one event — see [[Evidence System]].

## Not yet implemented
- Any real event ever being created by a detector — all events currently come from the seed script.
- Any linkage between an event and a specific camera/frame/model confidence score.

## Status
**Implemented** (schema + mock data + UI display), **Not Yet Implemented** (real event creation from detection).
